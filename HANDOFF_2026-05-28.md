## 5. CI pipeline (`.github/workflows/deploy.yml`)

Triggered on `push` to `main`. Two parallel jobs, both soft-fail
isolated so one outage can't block the other.

### Worker job

- Uses `cloudflare/wrangler-action@v3` (NOT raw `npx wrangler`).
- Sets `apiToken` from `CLOUDFLARE_API_TOKEN` secret + explicit
  `accountId: bb2863bb7e4de6f2d44fc5ea7dbef5cc`.
- Command: `deploy --keep-vars`. The `--keep-vars` flag stops
  wrangler from trying to delete environment variables that were set
  via the dashboard but aren't in wrangler.toml. Without it, every
  deploy would erase secrets.
- Hard-won lesson: `npx wrangler@latest deploy` deadlocked in CI on
  a remote-config-differs prompt that can't be answered. Don't go
  back to it.

  `unzip into deploy_staging/` → `SamKirkland/FTP-Deploy-Action@v4.3.5`.

## 6. Hard-won lessons (re-read before similar work)

### 6.1 BOM in Worker secrets

`wrangler secret put X` from a piped PowerShell string injected a
UTF-8 BOM (`﻿`) at the start of the secret. We caught it
because the Sentry DSN URL parser silently rejected it. Fix lives in
`worker-src/observability.js` — the `getConfig` path tolerates
leading BOM. If you ever add a secret and it "just doesn't work"
without an error, suspect BOM first.

### 6.2 Hostinger FTP chroot

The FTP user `u680581922.githubdeploy` is chroot'd INSIDE
`public_html`, not above it as the account-creation form's
"Directory: /public_html" field implies. So FTP `/` IS the live
DocumentRoot. Setting `server-dir: ./public_html/` created a phantom
nested `public_html/public_html/public_html/` directory that HTTP
never reads. Symptom: 5 "successful" CI deploys in a row, live site
still on the previous manual upload. Always sanity-check with
`curl -sI https://jamilformula.com/<file>` and compare Content-Length
+ Last-Modified against the local file.

### 6.3 LSCache + Cache-Control headers

Hostinger LSCache holds HTML for 1 hour (`max-age=3600`) and ignores
client-side cache-bypass headers (`Cache-Control: no-cache` etc.).
After a deploy, the new `?v=N` is on disk immediately but the live
site only reflects it after the cache TTL or a manual purge in
hPanel → Advanced → Cache Manager. Not a bug — just expected
behavior. Mention it to Jamil when he asks "why don't I see the
change yet?".

### 6.4 Sentry DSN format

Region matters. Jamil's DSN is in the `de` region
(`o4511451032387584.ingest.de.sentry.io`). The envelope endpoint
is `https://<host>/api/<projectId>/envelope/`. Our hand-rolled
sender in `worker-src/observability.js` parses the DSN manually.
If Sentry ever rejects events with 401, the DSN region or key
probably changed.

### 6.5 PostgREST DDL limit

You cannot run `CREATE TABLE` (or any DDL) via the Supabase REST API
from the Worker. The `exec_sql` RPC does not exist by default.
Migrations are manual: Jamil opens Supabase SQL Editor in his
browser and pastes the file. **Don't write a "do it for you" path
that doesn't exist.**

### 6.6 The "20-Phase super-prompt" trap

Last session over-committed to "Phase 2 through 9 while I'm out".
The session ran out of context after only 2.2 was actually committed
(the rest was edited locally but never pushed). Reality:
1 Phase per session, maximum. Ship it, verify it, then stop.

### 6.7 Positioning: English-first deliverables

Jamil corrected the consulting page when it said "PDF (Arabic or
English)". Formula AI Global is a global brand; the deliverable is
**English-first** (the global standard in industrial chemistry).
Translation to ANY language is "available on request". The site
navigation still flips Arabic/English via `data-i18n-ar` — that's
about the UI, not the deliverable. Don't roll this back.

### 6.8 Custom Project payment

Quick Diagnostic and Full Formulation Report show an inline "Pay Now"
button after the intake form because their prices are fixed.
Custom Project does NOT — it requires a discovery call first.
The Worker's `/be/consulting/pay` endpoint returns 409
`custom_needs_discovery_call` for that package by design.
